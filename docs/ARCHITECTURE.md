# Architecture

## Execution and data flow

React/Vite → local FastAPI commands → Jev research-program selection → persistent runner → public fetch/search → deterministic extraction → goal-specific Jev assessment and comparison → evidence validation → SQLite records/events → SSE → shared workspace views.

Jev is the semantic selector. Python owns URL validation, queue membership, deduplication, arithmetic, dates, budgets, request boundaries and execution. Page fetching, search, video-record acquisition and browser rendering resolve to fixed read-only implementations. No output becomes code, a shell command, an arbitrary request method or an unrestricted tool call.

1. Plan preview checks readiness and offers optional question/limit edits. On Start, a real Jev request selects the unit of investigation, method, two evidence priorities and discovery route from finite typed options. `program.py` supplies core criteria. With a configured text provider, `research_proposals.py` generates specific additional questions and queries, then asks Jev to accept or reject them before use. Without it, code expands the selected templates. Explicit custom criteria remain fixed. Program identity includes the plan and generative provider/model. Successful preliminary choices and validated proposals can be reused after an interruption; no model-written code executes.
2. The runner seeds a durable action queue. Selection considers at most 16 eligible actions, records omitted count, and includes explicit abstention. The SDK supports 255 Choice options; the local smaller limit bounds payload/attention. A single legal action skips inference. In adaptive mode, a bounded group of independent leads can receive one inspect/defer Choice per record, in one Jev request; accepted records run concurrently (at most three). Shadow source slots prevent page/domain over-admission, a temporary per-investigation allowance preserves final-work capacity, and each actual payload reserves atomically against the remaining budget. The protected allowance is released after completion or cancellation without changing prior usage. Reference prerequisites, search and rendering stay serial. Fixed-template mode retains its recorded periodic exploration step.
3. Search observations retain provider, position, query, region requested, language, time and errors. Result titles/snippets describe candidate actions. A video program uses Brave's dedicated video endpoint and preserves actual native metadata for recognized individual-video URLs. Articles and platform listing URLs do not become video evidence; skipped entries are counted. Discovered links and follow-up query candidates remain bounded and recorded.
4. HTTP is first. `aiohttp` uses a public-only resolver on actual connections, not a precheck followed by an unrelated DNS lookup. Every redirect is revalidated. HTTP/robots wait and page acquisition are measured together as fetch time; extraction time is measured separately.
5. The extractor preserves normalized text, structural chunks/offsets, headings, table rows, metadata, JSON-LD, canonical claims, language, links, dates and coverage. It selects up to 24 passages using lexical relevance plus opening context. The full bounded extracted text stays local. Source text is not guaranteed visually visible; rendered DOM and source extraction are labeled separately.
6. One same-state request batches relevance Score, page/entity Choice, exclusion Choice, original-data-claim Noul and evidence-span Choices. Later support questions run in a separate request because they depend on selected passages. A span is checked verbatim against stored normalized text before citation creation.
7. Finding support means the supplied passage addresses the scoped question. It does not certify the underlying business claim. Unknown and contradicted outcomes remain distinct. Host grouping does not imply cross-domain ownership. Video identities use canonical individual-video URLs so multiple videos from one platform remain distinct. Same-content snapshots retain discovery paths but do not multiply independent support. Cross-case assessments must refer to collected evidence; patterns and suggested explanations are not causal proof.
8. Prepared suggestions come from an editable finite action library. When budget allows, a separate Jev Choice prioritizes a specific experiment using the approved goal, linked evidence and uncertainty. The recorded suggestion snapshot does not silently change when a template is later edited.
9. Completion checks criteria coverage and failed actions in code. A Jev `stop` response is abstention, not completeness certification. Budget/time/source exhaustion returns partial coverage; provider/decision uncertainty can block the mission.

## Persistence

`storage.py` applies idempotent `migration.sql`: SQLite WAL, foreign keys, busy timeout, indexed records, mission-goal FTS5, plan versions, command idempotency keys, response reservations and a cache. A process-wide reentrant lock serializes writes. `mutate()` commits records, state and their event together. A record/event contains stable IDs and source mode; events have a per-mission sequence and schema version 1.

Each source, research program, decision, span, finding, entity, metric, import and action is a typed logical record in the shared records table. Bounded JSON payloads preserve flexible lens data without creating an enterprise schema layer. FastAPI input models reject unknown fields and enforce limits. Events are append-only; record snapshots in event payloads let replay reconstruct historical state rather than applying today's records to yesterday's event time.

SSE uses monotonically increasing per-mission IDs and honors `Last-Event-ID`. The UI batches refreshes for 250 ms and never starts a mission on load. Tables/cards are paginated; domain grouping keeps maps usable. Selection/filter state survives view switches. On process restart, running missions become interrupted and in-flight reservations become uncertain. Retry is explicit; completed actions remain completed.

Plan previews include deterministic source readiness: selected providers, configured keys, query allowance and supplied websites. A preset lens in preview is only initial preparation. The execution-time research program is selected by Jev and records the actual decision and model; it must not be labeled as a deterministic preview choice. Mission detail also includes a read-only outcome projection over existing records/events, including source-linked supported findings, candidate/reference distinction, gaps and the last run's stop reason. That projection makes no inference call and does not schedule work or rewrite older missions.

The UI starts on Live's question prompt. It never restores a saved investigation as the landing screen; saved work is opened explicitly. Starting a question opens the live scene, and Results presents the program and collected research items. The sequence projects recorded decisions, options, excerpts and timings; it does not create a second research narrative or invent an inference stage. The searchable Guide documents the workflow. Research defaults are stored locally and affect new plans; existing mission plans retain their history. Adding sources to a partial run uses the existing steer and retry commands, preserving evidence and remaining limits. Editing an already executed plan uses a fresh child mission with recent acquisition; it does not retry completed actions under changed questions. Unchanged experiment suggestions for the same plan/model reuse their saved priority decision instead of making a redundant paid request.

New UI plans default to automatic Brave discovery with optional seed URLs. Research-program query candidates come from the user's goal plus bounded templates selected by Jev's unit and discovery route. Later candidates can use actually observed source text. Domain-diverse batches prevent same-site links hiding unvisited candidates. Abstention defers the presented batch within that run while unseen eligible candidates remain. Search attempts are persisted and consume the query limit even on failure. Competitor completion additionally requires the configured number of candidate domains; it never establishes exhaustive market coverage.

With text generation enabled, the initial queue preserves query allowance for up to two generated follow-up rounds. A round uses current public evidence, missing questions and screened-out source observations, including a challenge checkpoint before concluding that criteria are covered. Screened-out titles, URLs and roles explain what failed to answer the question; they do not become supporting findings. Private, excluded, rejected or outdated sources remain outside this context. The context fingerprint includes these observations so newly inspected material can change the next proposal. Jev selects a proposed search or declines; selected queries reenter the ordinary search/acquisition/evidence loop. Unavailable or malformed generation permits the existing bounded Jev refinement path, while an explicit Jev decline does not trigger this fallback. Suggested business experiments remain separate, unperformed recommendations.

`text_model.py` uses server credentials and a selected provider/model, with separate call, token and dollar reservations and request events. OpenAI and OpenRouter receive strict JSON schemas with all object properties required and additional properties forbidden; task-specific Pydantic schemas also validate replies locally. Google Gemini uses the native generateContent endpoint with a header-only key, strict bare model IDs and a JSON schema. Thinking-token usage is counted as billed output; thought content is not retained. Only a single STOP-finished text candidate is accepted. Compatible endpoints use JSON-object mode; Anthropic uses its Messages protocol. No SDK retry, automatic model fallback or provider-generated tool execution is enabled. Schema-failure diagnostics retain bounded field paths and error types, not generated input values. Text latency, usage and estimated spend remain separate from Jev metrics.

`synthesis.py` assembles at most 15 KB of exact public finding passages and asks the text model for claims, recommendations and unknowns. Every factual claim must reference offered findings; invalid IDs and single-subject comparisons are rejected locally. A separate Jev call checks each remaining claim against its cited passages. Unsupported wording is withheld; hypotheses and partially supported premises stay qualified. Current answers bind to scope, evidence, source attribution and review state. Private draft caches avoid rebilling unchanged generation after a verification failure; default exports exclude those drafts and raw model request states.

Entity roles distinguish the focal product, candidate entities and background publishers. Per-source classification observations remain attached instead of silently taking the last page's classification. `landscape.py` projects current linked evidence into candidate/reference cards, distinct-query visibility and comparative experiment proposals. It neither invents companies nor turns provider positions into popularity. A comparative experiment receives a Jev-priority label only when it matches the recorded selection and saved suggestion inputs. Configuration reload updates backend keys without exposing them or making an inference call.

## Video evidence boundary

`Search.videos` requests at most eight records from Brave's official video endpoint, with the existing server-side Brave key. Endpoint entitlement, quota and access are account-dependent. Failures are recorded; they do not trigger a hidden web-search fallback. The parser retains native fields and rejects article/listing or unrecognized individual-video URLs.

`video.source_from_result` converts each accepted record into a source explicitly labeled search-provider metadata. Its exact text chunks retain field paths and offsets. Acquisition time, provider index position, search observation ID and original URL remain attached. No HTTP status or page-fetch duration is fabricated. Numeric views are accepted only when actually supplied; missing values remain null. An index page date is not asserted to be the upload date.

`video.enrich_video_source` can append metadata from an unambiguous matching publisher `VideoObject` in a permitted fetched page. It keeps existing page text and offsets and adds exact description/transcript fields and scoped counters. An unrelated embedded video cannot turn its containing article into the video's primary record. This adapter performs no audiovisual inference, download or transcription. Descriptions and metadata cannot establish unseen media features or the cause of popularity.

`video.enrich_youtube_source` reads a literal `ytInitialPlayerResponse` JSON assignment from HTML already acquired by the permitted fetcher. It requires the player ID and final page identity to match the originally requested canonical video URL. It keeps only title, author, description, validated numeric counters/duration and named upload/publication dates, with exact field-path evidence offsets. HTML/literal sizes are bounded; nonliteral JavaScript, malformed JSON and ambiguous or mismatched IDs are rejected. Streaming URLs, tracking data and raw player objects are not retained. No script, hidden player API, caption endpoint or media request is executed. A transcript is available only if a separate matching publisher metadata extraction actually supplied its text.

The retained publisher description can contribute up to eight unique observed public video URLs as discovery leads, with exact source offsets and field provenance. Private/credential-bearing URLs, article/listing links, self-links and player-stream data are excluded. Generic platform navigation is not queued as video research. These are navigation candidates subject to the normal action/depth budgets, not proof that the linked videos were inspected or that a tutorial is itself part of the requested population.

## Collection analysis

`corpus.py` projects the current public, unrejected source/assessment/finding records into a common question matrix, exact source excerpts, status counts and typed-feature distributions. It excludes stale, private, excluded, rejected and non-primary artifact observations. Unknowns remain in every denominator. Measurements use linked saved assessment requests; caches are counted separately and never treated as live provider work. The analysis window and active inference time are distinct from whole-run time. The projection makes no provider calls and works on saved research. Default exports use bounded deduplicated excerpts. Replay hides the latest collection projection rather than leaking future results into an earlier event.

## Caches, costs and models

Fetch TTL is one hour unless fresh acquisition is requested. Snapshots retain original retrieval time and cache labels. Semantic cache fingerprints include serialized state, full questions/rubric, candidate descriptions/order, plan version and model. Only pinned model IDs use the cache. Cached decisions are labeled and excluded from live timing/usage totals.

Before each SDK attempt, a synchronous reservation atomically checks per-mission attempt, conservative byte-based token upper estimate and spend limits. The SDK's own retry is disabled to prevent hidden attempts. Failures/timeout/cancellation retain uncertain reservations. There is no automatic paid retry. A successful response supplies actual usage once per response, no matter how many typed questions it answered.

Settings defaults are $5 Jev and $20 LLM per investigation. The Jev setting supplies new-plan defaults without changing saved plans. Text requests use the current LLM allowance against that investigation's retained usage, including on resume; spend settings cannot change during an active run. Text price estimates are bound to provider and model. A known catalog price or an explicit input/output estimate is required before reservation, and unknown pricing blocks the request. Each text call records its price basis and conservative reservation, replacing the estimate with reported token usage when available. Changing the current model or budget never clears previous usage. Search billing is separate, and these local estimates are not provider-enforced billing caps.

The independent `.runtime/live-testing-ledger.sqlite` retains cumulative development attempts and reservations across mission deletion or database recreation. Its initial shared cap is 200 attempts and $2 estimated spend. An explicitly authorized, ignored `.runtime/development-limits.json` may set `max_calls`, `jev_usd` and `text_usd`; it preserves previous rows and applies separate provider ceilings with a shared attempt ceiling. Ordinary app Settings do not alter this development-only cap.

The Jev direct endpoint and model are explicit; unrelated provider keys, environment gateway URLs and text helpers are never autodetected. Every completed response records its actual returned model. Jev version changes create an event boundary and request a pause. Optional generated answers remain subject to the evidence checks described above.

## Browser boundary

Ephemeral sandboxed Chromium has no personal profile or inherited API keys in its browser environment. The document is fetched and its redirects resolved before navigation; response redirects are never delegated to Chromium. Requests are intercepted and fulfilled through the validated HTTP fetcher; only GET/HEAD are legal. Service workers, downloads, WebSockets, private targets and known tracking endpoints are blocked. Per-render requests cap at 50; actions are navigate and inspect with actual outcome verification and a screenshot. Link targets have observation-local IDs and a DOM fingerprint; they are never reused for blind interaction.

Arbitrary clicking, typing, form submission and multi-step browser workflows are deliberately not exposed. The present useful path is HTTP research plus opt-in rendered reading. The remaining OS-level browser egress limitation is documented in SECURITY.md.

## Main modules

- `config.py`, `schemas.py`, `lenses.py`: server settings and bounded data contracts.
- `api.py`: local-origin/session policy, commands, SSE, imports, reviews, retention and exports.
- `storage.py`, `migration.sql`: persistent state and atomic event records.
- `security.py`, `acquisition.py`, `browser.py`: URL/network policy and extraction.
- `jev.py`: official SDK, validation, model boundaries, cache and budget reservation.
- `search.py`, `video.py`: bounded web/video query adapters, individual-video identities and exact metadata evidence.
- `program.py`: Jev-selected research units, methods, priorities and allowlisted criteria/query compilation.
- `research.py`: durable bounded orchestration and evidence integrity.
- `actions.py`: finite editable experiment templates and immutable prioritized suggestion snapshots.
- `metrics.py`, `imports.py`: scoped publisher counters, imported data and comparable cohorts.
- `reports.py`: telemetry, explicit experiment templates and portable structured reports.
- `outcomes.py`: source readiness and factual summaries of saved evidence and stop events.
- `landscape.py`, `evidence.py`: eligible evidence, company/reference comparisons, observed visibility and grounded experiments.
- `activity.py`: read-only projection of recorded Jev decisions, available options, evidence and timings for the visible activity view.
- `frontend/src/api.ts`: local API/session client and pure historical replay reconstruction.
- `frontend/src/App.tsx`: shared research workspace; source/decision logic remains on the backend.
- `frontend/src/JevActivity.tsx`, `ResearchMap.tsx`, `SettingsPanel.tsx`, `Guide.tsx`: recorded decision sequence, research graph, configuration controls and searchable guide.
