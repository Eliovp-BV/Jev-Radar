# Jev ecosystem review

Reviewed 2026-09-19, using [Jevable](https://jevable.com/) to discover projects and original repositories to check implementation details. A gallery demonstration is not proof of reusable code, reliability or speed. This review installed no packages, copied no source code and added no external service dependency to Radar.

## Verified source and dependency boundaries

- **Jev Search:** inspected revision [`8b34965`](https://github.com/superagents-lab/jev-search/tree/8b34965084be05bc2be8dffeb9c2d2887d7e9a54), including its README, package manifest and [MIT license](https://github.com/superagents-lab/jev-search/blob/8b34965084be05bc2be8dffeb9c2d2887d7e9a54/LICENSE). It uses Search1API plus a configured Jev provider, React/TanStack and Cloudflare tooling. Its optional provider fallbacks and account costs are not Radar's behavior. Radar keeps its existing Brave adapter and direct TypeSafe configuration.
- **json-render:** inspected revision [`3ad3818`](https://github.com/vercel-labs/json-render/tree/3ad381881194e7011ad3ccd6d668033495a06c29), its Jev composer/README and [Apache-2.0 license](https://github.com/vercel-labs/json-render/blob/3ad381881194e7011ad3ccd6d668033495a06c29/LICENSE). Its playground uses a dedicated Vercel AI Gateway key; the reusable composition API is experimental. The sample's business data is synthetic. A Radar integration would supply actual record-derived candidates and a compatible transport, not reuse demonstration data.
- **fast-jev-compaction:** inspected revision [`e3f262a`](https://github.com/tamaratran/fast-jev-compaction/tree/e3f262a7f4d42bd8dd32ced30d26176f7cb545b0), `src/compact.ts`, `src/client.ts`, its package manifest and [MIT license](https://github.com/tamaratran/fast-jev-compaction/blob/e3f262a7f4d42bd8dd32ced30d26176f7cb545b0/LICENSE). The package targets Node 18+ and a TypeSafe key; its message structures are for agent conversations, not Radar's source records. Context-selection accuracy and net request savings would need separate measurement.
- **Jev Ultrafast:** inspected revision [`1231850`](https://github.com/browser-use/jev-ultrafast/tree/1231850a0bf1a0c0341fe408ef1668dbbfdfac46), its README/manifest and [MIT license](https://github.com/browser-use/jev-ultrafast/blob/1231850a0bf1a0c0341fe408ef1668dbbfdfac46/LICENSE). It requires Python 3.12+, Browser Harness and HTTPX; typing requires a separate text-model connection. Its reported demonstration timings are not Radar measurements.

Repository licenses cover the relevant code, subject to their terms; they do not supply provider credentials, service rights or rights to third-party brand assets. Radar's own project license remains a separate release decision.

## Recommended order of further work

1. Improve evidence access and compare actual artifacts. More visual animation cannot supply a missing transcript, measurement or original record.
2. Evaluate semantic passage selection against the current lexical selection, preserving exact citations and reporting real request cost/time. Keep the existing behavior when no useful selection is available.
3. Add one optional goal clarification only where uncertainty would change the research unit, comparison population or time window. Keep ordinary prompts direct.
4. Consider adaptive report layouts and request-context pruning after measuring their value. Both should preserve existing evidence and work when a model request fails.

These are implementation priorities inferred from the reviewed projects and Radar's current architecture, not features promised by those projects or a claim that adding more model calls inherently improves research.

## Collection teardown reference

The [competitor-ad teardown demo](https://x.com/TheMattBerman/status/2100654891756589230) applies common typed questions across original ads and aggregates the resulting classifications. The public demo was inspected: it shows individual records, their question results, request timings, review flags and rollups with denominators. The root post was retrieved through X’s public embed; a complete author-reply thread was not available. Its reported count, time and cost are the author’s demonstration claims, not Radar benchmarks. The post does not establish that discovery and acquisition fit within its analysis clock.

Radar adopts the useful workflow pattern through bounded parallel assessment and an evidence-linked collection matrix for the user’s research questions. No StealAds integration, ad dataset, source code or performance claim was imported.
